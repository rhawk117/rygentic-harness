The plugin now targets Claude Code as its only harness. Models repinned to Claude ids everywhere they are routed — agent pins, ticket schema defaults, docs, fixtures, eval needles: scout and gitty-up on `claude-haiku-4-5`; budgetron, grumpy, and the engineer default on `claude-sonnet-5`; sunny, wingman, uncle-bob, and merge-vader on `claude-opus-5`; large-scope engineer derivation pulls `claude-opus-5`. Copilot harness surface removed: `scripts/install-copilot.sh` deleted, `docs/copilot.md` replaced by `docs/claude-code.md`, README repositioned; agents-md-init and promptlint keep their Copilot-target features because those generate artifacts for target repos, not this harness. `hooksmith` retargeted to Claude Code hooks end to end (settings-file config surfaces, PascalCase events, snake_case stdin payloads, exit 0/2 plus `hookSpecificOutput` output contract, nine rebuilt sample payloads); its `hooks-reference.md` is now a real events/payload reference instead of a byte-identical copy of the catalog. Two skills renamed as decisions of record: `formulate-plan` → `game-plan` and `finish-assembly` → `stick-the-landing` (datasets, routing table, and cross-references follow; history keeps the old names). Jira references scrubbed: boundary clauses, the interview step, the `jira-tickets` schema key, the `jira-cli` allowlist token, and jira-as-example content (wingman's worked example now caches GitHub API responses; near-miss trigger queries reworded to a generic tracker, collision function preserved). Mechanical defect fixes: sunny's `adversarial-critic` references corrected to `grumpy`, agents-md-init's missing `references/explorer-prompts.md` created, prepare-handoff's duplicated SPRINT.md spec deduped, lets-investigate's draft sentence rewritten, uncle-bob's repo-root fallback gained the `git check-ignore` guard merge-vader already had, merge-vader now cites the contracts.md severity table instead of restating it. Marketplace generalized and renamed to `rygentic-harness` (mightymodels is one plugin in it; existing installs must re-add the marketplace under the new name). The repository moved to a multi-plugin layout: the plugin's manifest, skills, and agents now live under `plugins/mightymodels/` (moved with `git mv`, history preserved), the marketplace manifest stays at the repo root and points there via its `source` path, and evals, tests, and docs remain top-level. pyproject version drift (0.4.0) fixed; all three manifests agree at 0.6.0. Replay parity against the recorded gpt-id sessions is intentionally lost with the repins; live-model eval re-runs for the edited skills with datasets (prepare-handoff, using-mightymodels, lets-investigate) are pending per the retention rule.

## 0.5.0 — external review fixes: rename completed, integrity checks, safe installer (2026-08-22)

Ten findings from an external review, fixed before release. The `plan-work` skill rename is now complete: `formulate-plan` is canonical everywhere (H1, docs, README, issue template, sibling skills, the `evals/datasets/formulate-plan` dataset, and the eval case specs); earlier changelog entries keep the old name as historical record. The misspelling of `using-mightymodels` (a missing "y") is corrected repo-wide, including dataset and case names. Ramp routing gained a canonical truth table in docs/workflow.md — `sm` with `plan-first: false` goes to inline-sendoff, every other (scope, plan-first) combination to formulate-plan — closing the gap that left `med` unrouted; other documents now point at the table. Review remediation routes by risk before source: Critical findings and security findings at High or above go to a full engineer regardless of which reviewer found them. The worker-state contract was corrected everywhere it appeared: worker conversational state is never authoritative, bounded follow-ups may reuse a worker, recovery state is externalized before the workflow advances (durable-before-advance ordering now in contracts.md), and independent verification uses a fresh context. New deterministic integrity tests (`tests/test_integrity.py`, in `make ci`) fail on references to nonexistent skills/agents, workflow transitions to absent stages, dataset dirs without skills, inventory drift between docs and disk, and routing-table gaps — the class of defect that let the half-rename ship. `scripts/install-copilot.sh` now records what it installs in `$COPILOT_DIR/.mightymodels-manifest` and never deletes a destination it does not own: colliding personal skills/agents abort the install with a message and survive uninstall. An explicit trust boundary landed in SECURITY.md and every agent contract (`<trust_boundary>`): repository and tool content is data, never instructions; embedded directives are reported, not followed. Doc drift swept: seven workers (not "four"), twenty skills with `crashout` documented, phantom `jira` and `thermo-nuclear-code-quality-review` entries removed, and "compile time" softened to the write-time refusal that actually happens. Eval re-run for the seven edited skills (CliExecutor through headless Claude Code, runner claude-sonnet-5, dispatch simulated, results in `evals/results/RESULTS-2026-08-22.*`): with-skill 43/44 vs baseline 19/44. The one with-skill miss is a known check artifact, not a regression: `ReviewAggregationSound._has_triple` expects `AGG-n`/`C-n` aggregate IDs that no skill or contract mandates, and the session's `REV-n`-labeled aggregate demonstrably carries all three deduped findings, dual provenance, the Critical mapping, and the new risk-first routing. The evaluator is left as is per the no-weakening rule; tightening the ID contract (or the heuristic) is an iteration-2 item. Trigger datasets remain unexecuted by design (retrieval-oracle specific).

## 0.4.0 — mightymodels rename + humansays toolchain (2026-08-20)

The plugin is mightymodels now: every occurrence renamed (package `mightymodels_evals`, `.mightymodels/` ticket dirs, manifests, docs, datasets, fixture templates), author set to BUSYSRE, LICENSE removed. Project restructured to the humansays shape: root `pyproject.toml` (Python 3.14; the package stays under `evals/src`), root `tests/`, `.ruff.toml` and `.pytest.toml` copied from humansays and adapted (curated rule set at line-length 90 replaces select-ALL; pytest 9 with coverage, random order, warnings-as-errors), scripts/ repurposed from humansays (log/format/lint/ci/precheck, commit-msg checker) plus `security.sh`, a six-class prompt-injection scanner over skills/ and agents/ (verified against planted overrides, pipe-to-shell, and zero-width Unicode; the PCRE arm fails loudly if a pattern cannot compile). Pre-commit hooks (ruff, markdownlint-cli2, whitespace, the security scan, commit-msg format; hook scripts stay 3.12-compatible), `.markdownlint*` config with the prose set now lint-clean, GitHub Actions CI (bootstrap composite action, lint + tests + security + gate jobs). `report.py` renders through Jinja2 with loops in the template instead of `__SLOT__` string replacement. The TC "move to TYPE_CHECKING" trio is off with a written rationale: 3.14 lazy annotations plus pydantic-evals runtime introspection make it a NameError generator. Replay regression preserved through the rename by migrating the recorded run trees (ticket dirs renamed inside each work repo, migration commits kept out of `src/` pathspecs, pre-existing dirty state left dirty): 65/65 with-skill vs 31/65 baseline, byte-identical verdicts.
