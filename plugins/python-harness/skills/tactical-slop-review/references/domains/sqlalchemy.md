# Domain: SQLAlchemy 2.0

Load when `survey` lists `sqlalchemy`. expert corrected these conventions more than once; apply them exactly.

- **No `Annotated` column aliases on models.** Every column gets its own inline `mapped_column(...)`, with single-column CHECK constraints, indexes and foreign keys declared on that column, so the class reads top to bottom as the whole table. `__table_args__` holds only multi-column constraints.
- **No registry `type_annotation_map`.**
- **Models are mapped dataclasses** (`MappedAsDataclass`) **with no relationships.** Navigation happens in repositories and queries, not through lazy-loading attributes.
- **Instance methods that state invariants are fine** on models.
- **One model per file** in an `entity/` directory.
- **Primary keys are UUIDv7** generated by a `server_default`.
- **Repositories own data access**; the guide's §7 applies: an adapter that translates dependency errors yields the repository only inside its error-translating context manager, so callers cannot forget the guard.
- **Unit of work and services** are `@dataclass(slots=True, frozen=True)` dependency holders with public fields, not hand-written constructors with private attributes.

Evidence: read the `entity/` modules directly (they are declarative and short); pylens failure-paths and resources questions for sessions and transactions.
