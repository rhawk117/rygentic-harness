# Configuration smell catalog

Six smells, from a June 2026 mining study of 100 top-starred repositories carrying an
`AGENTS.md` or `CLAUDE.md`. 91 of the 100 files had at least one. Prevalences below are from
that dataset.

Read this when auditing an existing file, or when a candidate rule feels borderline and you
need a sharper test than "does this seem useful".

## Lint Leakage (62%)

Rules a linter, formatter, or type checker already enforces deterministically.

The cost is not just wasted tokens. Agents over-comply with whatever is written, so a style rule
actively consumes attention that the architectural constraint next to it needed. Ruff, Prettier,
ESLint, Biome, gofmt, and rustfmt do this work faster, cheaper, and with perfect consistency.

**Detection**: does the file mention indentation, line length, tabs versus spaces, quote style,
semicolons, trailing whitespace, import ordering, or naming case conventions?

Before:

```markdown
## Python Style Guide
- Indentation: 2 spaces
- Line Length: Maximum 80 characters
- function_and_variable_names: snake_case
- ClassNames: CamelCase
- Imports: organized and sorted
```

After: delete the section. Add `ruff` to the project and a pre-commit hook. If the agent needs
to know the tool exists, one line covers it: "Run `ruff check --fix` before committing."

## Context Bloat (42%)

The file exceeds roughly 200 lines. The largest observed in the study was 1,477 lines across 27
sections.

Be careful about the reasoning here, because the usual justification is shakier than people
think. A controlled factorial study across 1,650 Claude Code sessions manipulated file size from
25 to 500 lines and found no detectable effect on compliance with a target rule, with
affirmative-null Bayes factor support. So "the model loses the rule in a long file" is not well
evidenced.

What is well evidenced: context files raise inference cost by over 20% while not improving task
success, and agents follow whatever is written too literally. So cut for **behavioral cost**,
not for length. A line that makes the agent do something unwanted is worse than three lines that
do nothing. The 200-line target is a useful proxy, not the underlying reason.

**Detection**: line count, plus per line, "would removing this cause a mistake?"

## Skill Leakage (35%)

Specialized, rarely-needed procedures sitting in the always-on file. They load into every
session regardless of relevance and compete with rules that matter every time.

Most frequently leaked categories in the study: testing (10 instances), workflow such as code
review and PR procedures (8), scaffolding (4), infrastructure (4), architecture (3).

**Detection**: what fraction of sessions in this repo actually need this? If it is a minority,
it belongs in a skill.

Before, in `AGENTS.md`:

```markdown
## Adding a new OS to quickget
1. Entry in `os_info()` case statement
2. `releases_<os>()` function returning available versions
3. `editions_<os>()` function if multiple editions exist
4. `arch_<os>()` function if ARM64 is supported
5. Download URL construction logic
```

After: move to `.claude/skills/adding-an-os/SKILL.md` with a description naming the trigger.
Both tools load it on demand and neither pays for it otherwise.

## Init Fossilization (24%)

The file was generated by `/init` or an equivalent and never revised. 24 of 100 files had
exactly one commit, and none of those repositories were dormant.

This matters more than it looks, because LLM-generated context files performed *worse* than no
context file at all in the ETH Zurich evaluation. An unreviewed generated file is not a neutral
starting point.

**Detection**: `git log --follow -- <path>` returns a single commit.

Update triggers worth telling the user about: the agent makes the same mistake twice; a code
review catches something the agent should have known; you type the same correction you typed
last session; a new teammate would need the same context.

## Conflicting Instructions

Two rules that cannot both be satisfied. Small prompt variations then produce different
behavior, because the agent follows a different inference path each time.

Worth knowing: the factorial study found that a contradicting instruction placed in a *secondary*
file did not measurably reduce compliance with the primary file's rule, with affirmative-null
support. So cross-file conflict may be less destructive than assumed. Within-file conflict is
still a genuine ambiguity and still worth removing, and conflict co-occurs strongly with bloat.

**Detection**: the same command with two different invocations; the same artifact assigned to
two directories; a rule and its negation.

Before:

```markdown
- Components should be placed in the `packages/ui/components` directory
## How to create a new component
- Create a new folder in `packages/components` with the name of the component.
```

After: pick one path. If both are real, say which case each applies to.

## Blind Reference

A path or document mentioned with no explanation of what it holds or when to read it. The agent
either ignores it or loads a large file for no reason.

This is the least-discussed smell and one of the easiest to fix. The rule of thumb from the
grey literature: if you only mention the path, the agent will often ignore it. You have to pitch
it on why and when to read the file.

Before:

```markdown
### Plugin System (v5.0 - Not Yet Available)
See `docs/plugin-reorg.md` for details.
```

After:

```markdown
### Plugin System
Planned for v5.0 and not yet implemented. `docs/plugin-reorg.md` has the target module
boundaries; read it only if you are changing `src/plugins/`.
```

## Co-occurrence

These do not appear independently. From association-rule mining on the same dataset:

- Conflicting Instructions plus Skill Leakage raises the probability of Context Bloat to 83%
  (lift 1.81).
- Conflicting Instructions alone raises it to 81% (lift 1.76).
- Skill Leakage raises the probability of Lint Leakage to 76%.

Practical read: bloat is usually a symptom rather than the disease. When a file is too long, look
for leaked skills and style rules first. Removing those normally fixes the length without any
line-by-line editing.
